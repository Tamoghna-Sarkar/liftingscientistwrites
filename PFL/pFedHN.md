# Personalized Federated Learning using Hypernetworks (pFedHN)

## 1. Introduction

Personalized Federated Learning (PFL) addresses the challenge of training machine learning models on non-IID data distributed across many clients. Each client has its own data distribution and benefits most from a personalized model.

Traditional federated learning approaches, such as FedAvg, train a single global model and perform poorly in heterogeneous data settings. The pFedHN framework proposes using **hypernetworks** to generate personalized models for each client, allowing for collaboration while respecting data diversity and reducing communication costs.

---

## 2. Core Concepts

### 2.1 Hypernetwork

A **hypernetwork** is a neural network that generates the parameters (weights) of another neural network. It maps a client-specific input (such as an embedding or ID) to a unique set of model parameters.

- Let `H_ϕ(z)` be the hypernetwork with parameters `ϕ` and input `z`.
- For a client `c`, `θᶜ = H_ϕ(zᶜ)` gives the personalized model for that client.

Hypernetworks enable:
- **Conditional generation** of models
- **Parameter sharing** via a central global model
- **Efficient personalization** without storing all client models

---

### 2.2 Comparison to FedAvg

| Property                  | FedAvg                                      | pFedHN                                                 |
|--------------------------|----------------------------------------------|---------------------------------------------------------|
| Model sent to clients    | Same global model `θ`                        | Personalized model `θᶜ = H_ϕ(zᶜ)`                      |
| Client update            | Local training, return full model            | Local training, return gradient wrt `ϕ`                |
| Server update            | Average client models                        | Update hypernetwork `ϕ`                                |
| Personalization          | None (or heuristic-based)                    | Built-in via per-client model generation               |
| Communication cost       | Scales with model size                       | Independent of model size                              |

---

## 3. Training Loop in pFedHN

### 3.1 Training Overview

The training proceeds in communication rounds between server and clients.

1. **Model Generation**:
   - Server generates personalized model `θᶜ = H_ϕ(zᶜ)` for each client.

2. **Local Training**:
   - Client trains `f_{θᶜ}` on its own data using standard SGD.

3. **Gradient Computation**:
   - Client computes gradient of its loss w.r.t. `ϕ`, using the chain rule (as `θᶜ` is generated by `ϕ`).

4. **Server Aggregation**:
   - The server collects gradients `∇_ϕ Lᶜ` from multiple clients and updates `ϕ`.

---

## 4. Communication Flow

### What is Sent and Received

- **Server → Client**: Personalized model weights `θᶜ = H_ϕ(zᶜ)`
- **Client → Server**: Gradient `∇_ϕ Lᶜ` (not the full model or local weights)

---

## 5. Why This Still Personalizes

Despite a single hypernetwork `ϕ` being updated:
- Each client provides **different input** `zᶜ` to the hypernetwork.
- Updates from client `c` affect how the hypernetwork maps `zᶜ` to `θᶜ`, not how it maps for others.
- Over time, `H_ϕ(zᶜ)` improves at generating the optimal model for client `c`.

The hypernetwork thus learns a **many-to-many mapping**:
\[
zᶜ \rightarrow θᶜ
\]
This is fundamentally different from averaging models.

---

## 6. Mathematical Formulation

Let client `i` have:
- Local dataset `Sᵢ = {(xⱼ, yⱼ)}`
- Local loss `ℓᵢ(x, y; θ)`
- Empirical risk:
\[
\mathcal{L}_i(\theta_i) = \frac{1}{m_i} \sum_{j=1}^{m_i} \ell_i(x_j, y_j; \theta_i)
\]

### 6.1 Objective in PFL:

\[
\min_{\Theta} \frac{1}{n} \sum_{i=1}^n \mathcal{L}_i(\theta_i)
\]

### 6.2 Reformulated for pFedHN:

\[
\theta_i = h(v_i; \phi)
\quad \Rightarrow \quad
\min_{\phi, v_1, ..., v_n} \frac{1}{n} \sum_{i=1}^n \mathcal{L}_i(h(v_i; \phi))
\]

- `h(·; ϕ)` is the hypernetwork
- `vᵢ` is the client embedding or descriptor
